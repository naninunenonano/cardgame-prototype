# GR召喚と枚数制限の例外

基準main: 116b0d1360736f30061fe1aea875d0df777feaeb。確定日: 2026-11-20。

|カード|ID|区分|色・レア|記載コスト|攻撃力/体力|採用・所持上限|
|---|---|---|---|---|---|---|
|ドゥザイコGR|exgkn1|GR|黒N|黒1＋無色1|2/2|6|
|音奏 プーンギ|rr4|通常|赤R|赤1＋無色1|1/2|4|

GRは独立した`gr`配列。0〜6枚、GRクリーチャーのみ。旧デッキに配列がなければ空として移行する。試合開始時にGRのみ独立してシャッフルし、通常山札・既存Bot構成は変更しない。

`grSummon`効果で先頭1枚を選び、既存の空きユニット枠選択UIから登場する。マナ・ストック・サイド使用権を消費しない。召喚酔いと登場時処理を適用する。空・7枠満杯・既存の登場禁止では不発となり、カードを減らさない。場を離れるGRは元の持ち主のGRデッキ末尾へ返す。破壊・バウンス・除外・マナ送り等で共通処理を使う。

プーンギは相手の呪文の無色コストを1体につき1増やす。色コスト・記載コストそのものは変えない。自分のターン中の相手の呪文宣言で、各個体のGR召喚を独立して待機登録する。呪文本体と移動の完了後に誘発を解決する。

`unlimitedCopies:true`を持つカードは、`DeckLibrary.sectionCapacity`を上限にする。通常40、サイドは既存の上限設定からキャラクター固定1枠を差し引く9、GR6。`individualDeckLimit`とキャラクター1枚は優先する。収集・生成・自動分解・編集・保存・検証は同じ`limit`を使う。CGP1形式のデッキコードは4区分とストック・進化ルートを保存できる。所持数はコードに含めず、読込後も所持検証を行う。

## 検証と既存仕様

- GR6枚、シャッフル、登場時・召喚酔い、無償召喚、各ゾーンからの返却、複数体退場・再利用、召喚不発。
- プーンギの加算・支払い不足・ターン/使用者判定・複数誘発・呪文解決後の順序。
- 所持6・7枚目分解・6枚生成、将来の通常40/サイド9例外、個別制限維持。
- 旧保存・GR保存・コード往復・所持不足・Bot戦準備、スマホ390px/PC1280px編集と配置選択。

既存の4枚シールド保存データ・既存のサイド上限互換は維持する。新GR区分はこれらと独立。

《紅蓮の疾駆者 レイヴ》は管理シートでは実装未定、現行ゲームにも未登録。今回の対象外のため追加しない。GR召喚は`canSide`等を呼ばず、キャラクターLvやサイド使用権を参照しないことを検証する。レイヴ実カードとの組み合わせは追加時の検証事項。
