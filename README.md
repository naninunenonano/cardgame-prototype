# cardgame-prototype — 盤面試作 Ver.0.6

自分（プレイヤー1）のターンだけを繰り返す壁打ち試作です。今回、基本戦闘・ユニット7枠と上書き・召喚酔い・手札調整・ドローによる山札切れを実装しました。

## 起動

既存のGitHub Pages URL、またはindex.htmlをブラウザで開きます。ローカルではstyle.css・mana.js・game.js・app.jsを同じフォルダに置いてください。ビルド・外部アカウント・APIキーは不要です。iPhoneではファイルプレビューではなくSafari等で公開URLを開きます。

## 開始設定

両者の固定60枚は赤・1〜12コスト各3枚（通常36枚）、赤基本土地24枚です。基本土地以外の同名3枚までを生成時に検証します。各通常カードはパワー＝合計コスト×1000、能力なし。土地はパワーを持ちません。攻撃力と体力には分けません。

初手7枚、各自1回のマリガン。0〜7枚をタップ選択して交換するか、そのまま開始します。交換順は「山札下へ戻す→同数ドロー→シャッフル」。両者の完了後に盾7枚を裏向きで配置し、自分の先攻第1ターンを開始します。追加ドローはなく、各自手札7・盾7・山札46です。サイドボードは従来と同じ空の10枚枠で、サイド全体への同名制限は追加していません。

## フェイズ

今回の試作順は、アンタップ→ドロー→メイン1→アタック→メイン2→エンドです。アンタップとドローは開始時に自動処理します。上部ボタンで攻撃せず進むこともできます。

アンタップでは自分のユニット7枠・ルリグ枠と土地を回復し、自分の場の召喚酔いを解除、土地配置回数を0へ戻します。相手、手札、山札、盾、サイド、トラッシュ、除外、チェックの向きは変更しません。ドローは先攻第1ターンだけ省略し、以降は1枚です。

土地配置とユニット使用はメイン1・2だけ。土地は両メインを合わせて1ターン1枚で、手札へ戻しても回数は戻りません。メイン2への移行でも回数を維持します。

エンドでは自分の手札が7枚を超えていれば、選んだカードをトラッシュへ送り7枚へ調整します。途中の超過では捨てません。選択完了まで次のターンは開始しません。相手は壁打ちで自分のターンを迎えないため、盾から増えた相手手札もその場では調整しません。

エンド後の「次のターン」も自分のターンです。相手の自動ドロー・回復・行動はなく、手動確認対象も自動変更しません。連打防止用のトークンと350msの抑止を設けています。

## 7枠の配置とマナ支払い

手札をタップ→「場に出す」→配置先→土地の支払い案を確認・変更→確定。空きがあれば空き枠を使い、7枚満杯なら自分の場の1枚を選んで上書きできます。確認画面に対象とトラッシュ送りを表示します。

確定時に手札・配置先・上書き対象・土地の所属／未使用／重複・量・色を再確認し、支払い・旧カードのトラッシュ送り・配置を一括処理します。キャンセルや支払い不能は無変更。二重確定も拒否します。土地・ルリグ等は7枠に数えません。手動移動や追加で満杯の枠へ重ねる操作も拒否します。

コストは不特定と白青黒赤緑を分離しています。赤Nコストは今回の仮配分として不特定N-1＋赤1。基本土地は1枚を使用済みにして赤1点として支払い、配置コストはありません。必須色を先に確保した自動案をタップで変更できます。独立したマナ生成・プール・ステップ消滅は未実装。判定はDOM非依存のmana.jsです。

手札に支払い可／量不足／色不足、土地・各カードに未使用／使用済み、場のユニットに召喚酔いを文字で表示します。「未使用土地から出せるマナ」は貯留済みマナではありません。

## 攻撃・ブロック・盾

アタックで自分の未使用ユニットを選び「本体へ攻撃」。通常の対象は相手本体だけです。今回の赤仮ユニットに相手ユニットを直接攻撃する能力は付けていません。

出したユニットは召喚酔いで同ターンに攻撃できず、次の自分ターンのアンタップで解除します。向きとは別のsickフラグを持ち、手動で縦向きにするだけでは解除しません。攻撃宣言時に使用済みになります。

攻撃に応答して、防御側がブロックなし／未使用のブロッカー1枚を選びます。召喚酔いでもブロック可能です。ブロックしたカードも使用済みにし、パワー比較します。

| パワー比較 | トラッシュへ送るカード |
| --- | --- |
| 攻撃側が高い | 防御側 |
| 同パワー | 防御側（攻撃側有利） |
| 防御側が高い | 攻撃側 |

場に残ったカードは使用済みのままです。ダメージの蓄積は管理しません。ブロック時は盾と本体へ追加処理しません。

ブロックなしならパワーによらず盾1枚を持ち主の手札へ。トリガーはありません。盾0枚なら「シールドなしで本体への攻撃が通った」と記録するだけで勝敗を判定しません。

確認用ブロッカーは「仮カード追加（補助）」で通常カードのパワーとブロッカー欄を指定し、相手の空き枠へ追加できます。初期60枚には能力を追加しません。

## 領域・山札・補助操作

退場、上書き、エンドの手札調整はトラッシュへ送ります。使用済みになっただけでは場に残ります。両者に別の除外ゾーンを設け、明示した手動移動だけで除外します。両領域とも枚数と一覧を確認できます。

ドローで最後の1枚を引いた瞬間に山札切れで敗北し、複数枚ドローもそこで停止します。トラッシュのリフレッシュは行いません。盾の配置・手動移動など、ドロー以外で0枚になっただけでは敗北にしません。既に空の山札への要求も実際のドローではないため、新たな敗北条件は追加していません。

手動移動・追加・ドロー・表裏／縦横／召喚酔い切替・回復・削除はルール外の補助です。手動の土地移動は配置回数を数えず、回数も戻しません。処理選択中と敗北後には使えません。手札公開、一覧、拡大、裏向き確認、山札上下、シャッフル、コンパクト表示は維持しています。

戦闘・支払い・手札調整の選択中はフェイズを進めません。選択画面を閉じた場合は「選択を再開」で戻れます。支払いを閉じる／キャンセルする場合は、カードと土地を変えず操作を終了します。

「初期状態へ」は確認後にカード、ターン・フェイズ、土地回数、召喚酔い、使用済み、処理中選択、敗北結果、マリガン、ログを初期化します。再読み込みでも新規開始です。

## 構造と検証

game.jsはDOM非依存のゲーム処理、mana.jsは色コスト判定、app.jsは画面と操作です。スマートフォンの7枠は3列で折り返し、カードを極端に縮めず領域内スクロールで確認できます。

- node model-test.cjs：32回の開始・マリガン、正確な60枚とパワー・能力なし、上書き保存／取消／失敗、召喚酔い、ブロッカー条件、3通りの戦闘、盾移動と0枚時ログ、エンド調整待ち、土地回数共有、相手不変、複数ドロー中の敗北と非ドロー除外、色指定を確認。
- node browser-test.cjs：390pxタッチ・1280pxのChromiumで開始、7枠、拡大、上書き、召喚酔い、同値ブロック、盾移動、エンド調整、トラッシュ／除外一覧、最後のドロー敗北、リセット、横幅超過とJSエラーなしを確認。
- node dom-test.cjs：jsdomで7枚選択と二重処理防止、ブロッカー追加フォーム、土地のパワー・能力除外、拡大、リセット、領域と用語を確認。

実機iPhone／iOS Safariは未確認です。ヘッドレス環境は日本語フォントがないため文言はDOMでも確認します。開発テストのライブラリは通常実行に不要です。CHROMIUM_PATHでブラウザ実行ファイルを指定でき、テストの画面記録は/tmpへ保存します。

今回の試作仕様は、7枠上書き、同値の攻撃側有利、通常攻撃で盾1枚、指定フェイズ順です。指定外の効果・能力、Bot、オンライン対戦は追加していません。
