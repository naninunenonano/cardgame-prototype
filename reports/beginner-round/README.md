# 初級Bot総当たり

既存の対戦エンジン・初級Bot・採用カードの観測器を利用する。対象は選択可能な初級Botのみ。先攻は対面内で交互に割り当て、エラー時は同じ先攻条件を新規シードで補う。最大50回の補充で完走できなければ集計を失敗させる。調査中にルールやデッキを変えた場合は別の検証IDで初めから取り直す。

## 実行

同じコードとデッキをチェックアウトして実行する。次回の比較では、既存のシード範囲と重ならない起点を `BOT_SEED_BASE` に、既存と異なる検証ID・出力ディレクトリを集計コマンドに指定する。対面ごとのシード領域は10万刻み。

```sh
mkdir -p /tmp/beginner-round
export BOT_SEED_BASE=8000001
node -e 'const a=require("./decks").selectableBeginnerBotIds; for(const [i,p] of a.entries()) for(const q of a.slice(i+1)) console.log(p+":"+q)' |
  xargs -P 5 -I % sh -c 'BOT_PAIR="$1" node beginner-matchup-test.cjs 200 --beginner-round > "/tmp/beginner-round/$1.jsonl"' _ %
node beginner-round-report.cjs reports/beginner-round/2026-11-06 \
  "$(git rev-parse HEAD)" beginner-round-2026-11-06 /tmp/beginner-round/*.jsonl
```

特定試合を再現する場合は、記録の `p1` と `p2` をその順で使い、`first` を明示する。

```sh
BOT_PAIR=blueBeginner:redBeginner BOT_REPLAY_SEED=8000001 BOT_REPLAY_FIRST=p1 \
  node beginner-matchup-test.cjs 2 --beginner-round
```

ゲーム判断に用いる乱数は既存のシード付き生成器から供給する。実行日時と内部監査IDは実行ごとに変わる。勝率は（勝ち＋引き分けの半分）÷正常終了数。異常はシード・先後・手番・理由とともに別記する。

## データ

- `results.json` は10対面の先後別ライフ曲線と、5デッキの成績・採用スナップショット・カード評価・異常終了を収録する。デッキ版は採用構成のSHA-256の先頭12桁。
- `games-*.jsonl.gz` は全試合を対面別に分割した記録。`gzip -dc` で読み出せる。ライフ・マナ・手札・生存は `p1,p2` 順。ライフ差はそのターンの手番側基準。決着ターンは最終状態を含む。
- ターンの横軸は両Bot共通の手番通し番号。決着後のターンは補完せず、各点の試合数も保持する。終盤の平均には長期戦だけが残るため、全試合の巻き返しとは区別する。
- 採用カードの使用は登場・設置・呪文宣言・シールド発動・成長を既存観測器で計上する。チャージは別集計。候補はカードID単位。同一試合の判断機会数は複数回になりうる。
- 「未使用」は試合中に使用されなかった件数。終了時に手札に残ったカードID、未発動の自動シールドの潜在発動機会、すべての間接効果は個別に計測していない。判断の見送りは、そのカードを選べた時点で別の行動を選んだ回数であり、誤判断の確定数ではない。
- 観測点は既存の5デッキ調査と同じ重み付け。ダメージ・除去・バウンス・ハンデス・ドロー・回復・ブロック・軽減の観測であり、因果効果ではない。マナ配置・支払いは別項目。

調整する際は、候補の承認後にコード側でデッキを変更する。新しいデッキ版と検証IDのスナップショットを追加し、過去の構成・勝率・相性を保持する。シートの候補・承認欄はゲームのデッキと自動連動しない。
